# ByteSRC 漏洞判定规则详解

本文件定义字节跳动安全响应中心（ByteSRC, src.bytedance.com）漏洞报告的三级判定规则体系：不符(F)、保留(R)、属实(T)，以及 ByteSRC 专属的六级等级判定与业务系数档位。

> 依据：`/home/my/SRC/BSRC/markdown/ByteSRC安全报告处置规则V6.0.md`
> 核心红线：只允许**手工测试**，禁止扫描器/自动化工具；禁止任何 DoS/DDoS；禁止内网渗透；越权读取真实数据 ≤5 组；所有敏感测试行为（反弹shell/容器逃逸/改密/删改数据/文件上传等）**必须提前报备**。

---

## 一、判定为"不符"的规则 (F-01 ~ F-05)

判定为"不符"的漏洞报告存在根本性缺陷，不在 ByteSRC 收录/奖励范围内。

### F-01 — 资产/收录范围不符

**条件：** 漏洞URL对应的资产不在 ByteSRC 收录范围内。

**关键信号：**
1. 与字节跳动（中国区）业务无关的漏洞
2. **非字节（中国区）研发/运维的第三方供应商漏洞**：第三方维护的小程序、API站点、服务器、营销活动、外包系统、抖音电商 ISV 等
3. 火山引擎、BytePlus 外部客户的漏洞
4. 非中区产品及应用（应转交 security@bytedance.com 而非平台提交）
5. 高/中/低系数表中未覆盖、且非字节（中国区）研发运维的产品

**置信度：** 99%

### F-02 — 报告书写过于简单无法复现

**条件：** 提交的报告书写过于简单，无法根据报告内容复现（含与审核员反复沟通均无法复现的漏洞）。

**关键信号：**
1. 仅有文字描述或理论猜测，无任何复现细节
2. "漏洞详情"为空或仅一句话；"复现步骤"仅一个URL，无数据包、无响应对比、无利用证明
3. 报告主要内容是扫描器/Hunter/FOFA 截图
4. 未提供成功案例，只是说明理论可行的（如纯猜测、无法重现、未经验证、无意义扫描报告）

**置信度：** 100%

### F-03 — 漏洞本身不成立或无危害

**条件：** 无法利用（包括利用条件苛刻）或无危害。

**关键信号：**
1. 页面显示功能错误（如 Swagger UI 显示 "Failed to load API definition"），无实际利用可能
2. 恶作剧 CSRF（对用户无实际影响）、Self-XSS
3. 无法影响他人的本地拒绝服务、无法远程利用的 dll 劫持、静态文件目录遍历
4. 简单 DNS 日志型 SSRF
5. 用户名遍历、SPF 邮件伪造
6. 符合业务预期的产品设计

**置信度：** 95%

### F-04 — 明确不在奖励范围（ByteSRC 忽略清单）

**条件：** 属于 ByteSRC V6.0 忽略清单的明确不收项。

**具体子类：**
- **内部已知**：通用平台如 Jenkins 等已在网络上公开的漏洞、内部安全人员已发现的漏洞、已有其他白帽子优先提交的漏洞
- **专项排查中**：某系统/某类型漏洞内部展开统一专项治理时暂不收取
- **模型/内容安全**：与模型提示和响应内容相关的问题暂不收取、非信息安全漏洞导致的内容安全风险不收
- **隐私合规**：「隐私合规」相关问题暂不收取
- **电商越权**：电商业务中的子主账号越权问题暂不收取
- **无影响越权**：无任何意义或影响的越权（无法影响他人的越权不收取）
- **网络层DoS**：基于网络层面的拒绝服务攻击、无法影响他人的本地拒绝服务不收取
- **Github泄露**：GitHub 等平台泄露源代码直接提交不深入验证（AK/SK 类直接提交平台，由审核验证）

**置信度：** 98%

### F-05 — 违反测试红线

**条件：** 测试行为违反 ByteSRC 测试规则（第2章），或未经报备的敏感测试。

**关键信号：**
1. 使用扫描器/自动化工具产生大量流量（仅允许手工测试）
2. 越权批量读取真实数据 >5 组、进行批量枚举遍历
3. 内网渗透/横向移动/上传 webshell/反弹 shell 未报备
4. 影响线上真实业务与用户数据、向真实用户发送测试信息
5. 使用违反平台规定或法律法规的文字/图片/视频作为测试素材
6. AK/SK 泄露类报告擅自深入业务验证危害（应直接提交平台）

**置信度：** 95%

## 二、判定为"保留"的规则 (R-01 ~ R-04)

判定为"保留"的漏洞报告存在一定安全隐患，但缺乏直接、完整的危害利用证明，或属于低危/边缘场景，需进一步观察或组合利用。

### R-01 — 轻微信息泄露

**条件：** 轻微信息泄露漏洞（ByteSRC 归低危）。

**关键信号：**
1. 路径泄露、.git 文件泄露、Django Debug、phpinfo、服务端业务日志内容、CORS 导致的敏感信息泄漏
2. 非敏感信息泄露（内网 IP、域名）→ 不收，降级 F
3. 普通信息泄露（含敏感信息的完整源代码泄露）→ 中危，可 T

**置信度：** 85%

### R-02 — 漏洞利用门槛高或无法独立造成危害

**条件：** 可用于钓鱼/黑产但危害受限，或难以利用。

**关键信号：**
1. 反射型 XSS、无交互的任意 url 跳转（低危）
2. 难以利用但存在安全隐患的漏洞（如测试系统的 SQL 注入点）
3. Blind 类 SSRF（服务器执行了攻击请求但不返回任何可观察的响应差异 → 低危3级）
4. 攻击链不完整，无法独立完成攻击
5. 利用成本高、变现困难、影响范围小（不能转卖/变现的资源、仅攻击者个人账号获取资源收益、新客优惠等实际业务损失有限）

**置信度：** 90%

### R-03 — 系统/服务本身的暴露但未深入利用

**条件：** 系统接口/服务暴露，但无法证明获取了有价值数据或进一步利用。

**关键信号：**
1. 报告核心是利用 `/swagger-ui.html` 或 Webpack 路径的发现
2. 提供了管理界面截图但未展示任何可读取的敏感数据
3. SSRF 仅能访问 DNSLog，无法获取内网信息或凭证

**置信度：** 85%

### R-04 — 利用价值低的逻辑/频控缺陷

**条件：** 频控缺陷或低价值逻辑问题。

**关键信号：**
1. 频控缺陷（短信轰炸、用户账户密码暴力破解）→ ByteSRC 低危
2. 绕过限制使用一部分高级服务/获取优惠（基础版用户越权接口获取高级版服务、大量重复享受有限优惠但仅特定非核心资源）→ 中危
3. 登出后 Token/Session 未失效但无敏感权限

**置信度：** 80%

## 三、判定为"属实"的规则 (T-01 ~ T-02)

### T-01 — 完整攻击链或直接利用危害

**条件：** 报告能从一个未经认证的入口点，通过一系列组合漏洞，清晰、完整地证明对业务或数据造成实质性损害的过程，而非理论猜测。

**关键信号：**
1. 漏洞危害：任意账号登录/改密、越权操作他人账户全部或部分核心功能、获取大量用户隐私数据、任意资金消费/无限制提现等
2. 攻击链清晰：`[A漏洞] → [B漏洞] → [C危害]`，每一步都有完整请求/响应包
3. 报告明确展示了实际影响，如修改数据后的数据库截图（而非页面提示）

**置信度：** 99%

### T-02 — 未授权访问高敏感数据

**条件：** 未经认证直接获取、列举或下载包含大量用户核心敏感信息（身份证号、手机号、银行账号、密码哈希、详细交易记录等）或企业核心数据。

**关键信号：**
1. URL/接口直接返回包含大量用户信息的 JSON/CSV 数据
2. 证明具备批量获取数据能力（如修改 ID 参数遍历）——但**测试时仅需证明可读取，真实数据不超过5组**

**置信度：** 99%

## 六、401/403 处理规则

- **401/403 响应 ≠ 存在未授权漏洞**
- 不能以返回 401/403 的端点声称"未授权访问"
- 除非证明存在：认证绕过方式、响应体实际含敏感数据、或不同路径绕过
- **公开数据接口**（开放 API 目录、数据平台、天气/股票 API 等）不算未授权
- **SPA catch-all 页面**（前端框架所有路由都返回 200 + index.html）不算有效端点

## 七、报告书写规范（影响报告质量奖励 1-50 附加分）

报告须包含：
1. **漏洞标题** — 包含漏洞题目、影响域名、漏洞类型
2. **漏洞描述** — 包含漏洞的入口、涉及的 URL、参数、应用版本
3. **复现过程** — 按步骤复现并体现影响与危害，一般以文字截图形式；若使用工具请提供工具名称
4. **修复方案** — 可执行的修复建议（代码修复建议或防护策略）

**测试素材红线：** 禁止使用任何违反平台规定或法律法规的文字、图片、视频作为测试素材，或上传至 ByteSRC 平台。
