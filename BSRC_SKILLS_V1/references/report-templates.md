# 报告模板参考

## 标准漏洞报告模板

```markdown
# [厂商名称] - [漏洞简述]

## 漏洞信息
| 项目 | 内容 |
|------|------|
| **漏洞名称** | XXX |
| **漏洞等级** | 严重/高危/中危/低危 |
| **漏洞类型** | XXX |
| **影响范围** | URL/域名 |
| **发现时间** | YYYY-MM-DD |

## 漏洞描述
[技术性描述：成因、发现过程、攻击者如何利用]

## 漏洞复现
### 复现1：[步骤描述]
```http
GET /path HTTP/1.1
Host: target.example.com

HTTP/1.1 200 OK
{"sensitive": "data..."}
```

## 漏洞影响
1. **影响点1**：详细说明

## 修复建议
### 紧急措施（24小时内）
### 短期措施（1周内）
### 长期措施

## 验证记录
| 端点 | HTTP状态 | 有效 |
|------|----------|------|
| /api/xxx | 200 OK | 有效 |
```

## 利用链/组合漏洞报告模板

```markdown
# [厂商] - 多漏洞组合利用链

## 漏洞概述
| 项目 | 内容 |
|------|------|
| **链名称** | XXX |
| **最终等级** | 严重/高危 |
| **漏洞数量** | N个 |
| **影响范围** | URL/域名 |

## 攻击链路图
```
入口: 漏洞A(信息泄露) → 获取凭证
  ↓
跳板: 漏洞B(未授权) → 访问内部系统
  ↓
提升: 漏洞C(越权) → 管理员权限
  ↓
最终: 漏洞D(RCE/数据泄露)
```

## 漏洞A：[名称]（复现步骤+请求/响应包）
## 漏洞B：[名称]（同上）
## ...（按链顺序列出）

## 最终影响
完整攻击链能达成的效果

## 修复建议
### 紧急：阻断链路入口或关键跳板
### 短期：各漏洞逐一修复
```

## 文件命名规则

```
{严重等级}_{漏洞类型}_{公司简称}_{简述}.md
严重_未授权访问_林长制系统_管理后台未授权.md
高危_信息泄露_建筑工人平台_Handler接口泄露.md
```

## 低危报告输出控制

仅在严重→高危→中危全部完成后，且具有组合升级潜力时，才输出低危报告。
