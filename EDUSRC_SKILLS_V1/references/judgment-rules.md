# EDUSRC 漏洞判定规则详解

本文件定义EDUSRC（教育漏洞报告平台）漏洞报告的三级判定规则体系：不符(F)、保留(R)、属实(T)。

---

## 一、EDUSRC 评分标准（Rank 0-10）

| 等级 | Rank分值 | 条件 |
|------|---------|------|
| **严重** | 9~10 | 直接获取服务器权限、重要系统SQL注入、核心机密泄露 |
| **高危** | 7~9 | 普通系统权限、严重逻辑缺陷、批量用户权限、严重权限绕过 |
| **中危** | 4~7 | 条件限制下的权限获取、文件操作、水平权限绕过 |
| **低危** | 0~4 | 非核心数据、条件严苛下的操作、需用户交互的漏洞 |

### 严重漏洞（9~10 Rank）

1. **直接获取服务器权限**
   - 远程命令执行（RCE）
   - 上传webshell
   - 可利用的远程缓冲区溢出
   - 远程内核代码执行

2. **严重信息泄露**
   - 重要系统SQL注入获取大量数据
   - 直接获取目标单位核心机密

3. **可利用的代码执行**
   - ActiveX堆栈溢出/浏览器Use After Free
   - 因逻辑问题导致的远程代码执行

### 高危漏洞（7~9 Rank）

1. **权限获取**
   - 远程命令执行、代码执行
   - 上传webshell
   - 缓冲区溢出

2. **严重逻辑/流程缺陷**
   - 任意账号密码修改
   - 重要业务配置修改
   - 严重信息泄露

3. **批量用户权限**
   - 普通系统SQL注入
   - 用户订单遍历

4. **权限绕过**
   - 绕过认证直接访问管理后台
   - Cookie欺骗

5. **运维未授权**
   - 后台管理员弱口令
   - 服务未授权访问

### 中危漏洞（4~7 Rank）

1. **限制性权限获取**
   - 交互性代码执行
   - 一定条件下的注入
   - 特定系统版本下的getshell

2. **文件操作**
   - 任意文件写、删除、下载
   - 敏感文件读取

3. **水平权限绕过**
   - 绕过限制修改用户资料
   - 执行用户操作

### 低危漏洞（0~4 Rank）

1. **非核心数据** — 获取一些非核心数据
2. **条件严苛** — 在严苛条件下获取核心数据
3. **需用户交互** — XSS、CSRF、点击劫持

## 二、EDUSRC 忽略清单

以下漏洞将被忽略（不予奖励）：

| 编号 | 类型 | 说明 |
|------|------|------|
| I-01 | 非教育行业 | 确认不属于教育相关行业的单位 |
| I-02 | 虚假漏洞 | 提交不存在的漏洞 |
| I-03 | 重复漏洞 | 平台上已有的报告 |
| I-04 | 已公开漏洞 | 互联网上已公开的漏洞 |
| I-05 | 一洞多投 | 提交到本平台后又提交到其他平台 |
| I-06 | 信息不全 | 无链接/截图/利用方法的漏洞 |
| I-07 | 需管理员后台 | 需要登录管理员后台才能触发的漏洞 |
| I-08 | 中间人攻击 | 需要MITM的漏洞 |
| I-09 | Self-XSS | 仅影响自身的XSS |
| I-10 | 无敏感CSRF | 无敏感操作的CSRF |
| I-11 | 钓鱼漏洞 | 钓鱼相关的漏洞报告 |
| I-12 | 无敏感JSON Hijacking | 无敏感信息的JSON劫持 |
| I-13 | 扫描器结果 | 扫描器获取但无法提供利用方法的漏洞 |
| I-14 | 无意义泄露 | 无意义的源码泄露、内网IP、域名泄露 |
| I-15 | 拒绝服务 | DoS/DDoS漏洞 |

## 三、判定为"不符"的规则 (F-01 ~ F-04)

### F-01 — 资产不在EDUSRC收录范围

**条件：** 漏洞URL对应的资产不在EDUSRC收录范围内。

**确认方法：**
1. 确认目标是否为以下类别：教育部、人社部、中科院、各级教育/人社行政部门、各级学校/技校、教育软件
2. 教育局认证的中小学不确认归属的，以备案单位为准
3. 学校和商业公司联合运营的平台，以主办方性质判断

**置信度：** 99%

### F-02 — 报告不符合基本要求

**条件：**
1. 仅有文字描述或理论猜测，无任何复现细节（无链接/截图/利用方法）
2. 仅提供资产测绘、API端点列表，未证明任何实际漏洞或危害
3. 漏洞详情栏目为空或内容不完整

**置信度：** 100%

### F-03 — 漏洞本身不成立或无危害

**条件：**
1. 页面显示功能错误，无实际利用可能
2. 信息泄露不包含任何敏感数据
3. 被WAF拦截或防护措施有效，无法证明可绕过

**置信度：** 95%

### F-04 — 漏洞类型明确在忽略清单中

**条件：** 属于EDUSRC忽略清单的类型（见上表I-01至I-15）。

**常见误报：**
1. Self-XSS
2. 无敏感操作的CSRF
3. 扫描器结果无利用方法
4. 无意义的源码泄露

**置信度：** 98%

## 四、判定为"保留"的规则 (R-01 ~ R-04)

### R-01 — 非敏感信息级泄露

**条件：**
1. 调试信息、PHPInfo等泄露但不含核心数据
2. 少量经授权的公开个人信息
3. 一般信息的日志泄露

**置信度：** 85%

### R-02 — 漏洞利用门槛高

**条件：**
1. 需用户交互（反射型XSS/CSRF）
2. 无法完整利用（SSRF仅到DNSLog）
3. 攻击链不完整

**置信度：** 90%

### R-03 — 系统暴露但未深入利用

**条件：**
1. 系统接口泄露（Swagger/Webpack）
2. 未授权服务暴露但无法证明数据获取
3. 需进一步利用的开放注册

**置信度：** 85%

### R-04 — 利用价值低的逻辑缺陷

**条件：**
1. 登出后Token未失效但无敏感权限
2. 仅有验证码校验缺失（已有IP/账号限制）
3. 扫描结果常见但利用难度极高

**置信度：** 80%

---

## 五、判定为"属实"的规则 (T-01 ~ T-02)

### T-01 — 完整攻击链或直接利用危害

**条件：** 能从未经认证的入口点，通过一系列组合漏洞，清晰完整地证明对业务或数据造成实质性损害。

**置信度：** 99%

### T-02 — 未授权访问高敏感数据

**条件：** 未经认证，能够直接获取、列举或下载包含大量学生核心敏感信息（身份证号、成绩、家庭信息）的数据。

**教育行业特例：**
- 录取公示名单（姓名+考生号） — 中危
- 批量成绩/课程数据 — 高危
- 学生全套档案（含身份证+家庭住址） — 严重
- 教职工通讯录 — 中危

**置信度：** 99%

## 六、等级降级规则

存在以下情况酌情降低等级：

1. **WAF不可绕过** — 漏洞真实存在但无法说明利用方法
2. **已知漏洞** — 提交前单位已知晓但暂未修复
3. **条件偶然性** — 触发需要一定条件，具有一定的偶然性
4. **多处相似** — 同一单位多处相似漏洞
5. **夸大危害** — 恶意夸大漏洞危害
6. **方式相似** — 非同一单位但利用方式相似的
7. **公开通用型** — 已公开利用方式的通用型安全漏洞
