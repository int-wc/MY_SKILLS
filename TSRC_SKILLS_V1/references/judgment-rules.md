# TSRC 漏洞判定规则详解

本文件定义TSRC（腾讯安全应急响应中心）漏洞报告的三级判定规则体系：不符(F)、保留(R)、属实(T)。

---

## 一、判定为"不符"的规则 (F-01 ~ F-06)

判定为"不符"的漏洞报告存在根本性缺陷，不满足TSRC奖励计划的最低要求。

### F-01 — 资产所有权不符

**条件：** 漏洞URL对应的资产不在TSRC明确收录范围内（非腾讯产品/业务/资产）。

**关键信号：**
1. URL/IP不属于腾讯旗下产品或业务（需对照腾讯资产清单确认）
2. 资产为腾讯云上运行的第三方客户业务（腾讯云有大量第三方客户，IP ≠ 腾讯资产）
3. 资产属于收购子公司且不在TSRC范围（如搜狗、腾讯音乐TME、阅文等独立子公司）
4. 非腾讯进行开发、运维和运营的应用/小程序后端API站点

**置信度：** 99%

### F-02 — 报告内容不符基本要求

**条件：**
1. 仅有文字描述或理论猜测，无任何复现细节
2. 仅提供资产测绘、API端点列表，未证明任何实际漏洞或危害
3. 附件作为主要依据，漏洞详情栏目为空或内容不完整

**关键信号：**
1. 报告"漏洞详情"为空或仅一句话
2. "复现步骤"仅包含一个URL，无数据包、无响应对比、无利用证明
3. 报告主要内容是FOFA/ Hunter扫描结果截图

**置信度：** 100%

### F-03 — 漏洞本身不成立或无危害

**条件：**
1. 页面显示功能错误（如Swagger UI显示"Failed to load API definition"），无实际利用可能
2. 报错信息不包含任何敏感数据

**关键信号：**
1. Swagger页面报错"Failed to load API definition"
2. 响应包仅包含通用错误信息，如"404 Not Found"、"Internal Server Error"
3. 仅能调起系统自带程序，无法执行任意命令

**置信度：** 95%

### F-04 — 漏洞类型明确不在TSRC奖励范围

**条件：** 属于TSRC漏洞奖励计划明确不收录的漏洞类型清单。

**TSRC 明确不收录 / 忽略的类型：**

**信息泄露类：**
- 不涉及敏感信息的CORS配置错误
- 无意义的内存/日志/内网IP泄露
- 示例文件泄露、无意义的API Key泄露
- 前端源码泄露（SPA源码泄漏非未授权漏洞）
- 无敏感信息的JSON Hijacking

**功能缺陷类：**
- 业务预期内的功能/bug（网页乱码、无法打开等）
- 符合业务预期的产品设计
- 无法造成资金损失的逻辑问题

**大模型相关（不收录）：**
- 越狱/安全绕过（DAN等提示词）
- 大模型输出恶意内容（违规营销、恶意代码）
- 模型幻觉（诱导模拟终端并执行命令）
- 非隐私数据泄露的AI服务风险（Jailbreak、Prompt Leak）

**其他：**
- 隐私合规相关问题
- 沙箱环境中的代码执行（除非逃逸）
- 利用场景单一、利用凭证复杂的逻辑漏洞（如8位以上无规则ID遍历）
- 横向短信轰炸
- Self-XSS
- 无敏感操作的CSRF（收藏、添加购物车等）
- 401/403页面（除非绕过或含敏感数据）
- 无实际意义的扫描器漏洞报告
- 无任何证据的猜测
- 内部安全人员已发现的漏洞（2个发版周期内）

**置信度：** 98%

### F-05 — SSRF 违反 TSEC 测试规范

**条件：** SSRF测试未使用TSRC指定的测试域名/IP，或对内网服务进行了扫描。

**正确做法：**
- 全回显SSRF测试域名：`http://tst.woa.com/flag.html`
- 全回显SSRF测试IP：`http://9.138.237.216/flag.html`
- 仅验证回显，不得对内网服务进行扫描

**置信度：** 100%

### F-06 — 数据量/影响范围不符合TSRC收录门槛

**条件：**
- 高危及严重漏洞：存量影响用户量<10%
- 中低危漏洞：存量影响用户量<50%
- 数据泄露 < 1万条
- 敏感字段 < 3个

**置信度：** 90%

## 二、判定为"保留"的规则 (R-01 ~ R-04)

判定为"保留"的漏洞存在某种程度的隐患，但因门槛较高/影响有限/信息不足暂不做最终判定。

### R-01 — 非敏感信息泄露，或有利用门槛

**条件：** 泄露了信息但敏感度低，或有技术要求/条件要求导致门槛较高。

**示例：**
1. 网站报错信息含服务器路径但不含敏感数据
2. 仅泄露不太可能被利用的服务器进程路径（如 `/home/nginx/html/xxx/js/1.js`）
3. 某些日志文件或调试信息但无法进一步利用
4. 401/403响应体为空或仅通用权限错误
5. 需要中间人攻击的漏洞（除非能证明实际可行）

### R-02 — 特定模块或非核心产品

**条件：** 漏洞存在于边缘功能、非核心产品中，利用价值有限。

**TSRC 上下文：**
- 其他产品（非核心/非重点）的低中危漏洞奖励较低
- 测试系统/容器环境无法证明通往生产环境的路径

### R-03 — 信息不足以判断

**条件：** 仅看到疑似路径或端点，但 curl 返回 404 或超时，无法确认实际存在。

**处理建议：** 标记待验证目标，获取更多信息（如 Cookie/特定 Header）后再测。

### R-04 — 客户端漏洞/需要用户交互

**条件：** 需要用户完成特定交互才能触发，利用难度高。

**TSRC 上下文：**
- 需要用户交互的漏洞在原评级基础上降级处理
- 超过两步交互的漏洞视为高交互
- 客户端漏洞审核时间较长，需提供 poc + 验证视频 + 详细分析

## 三、判定为"属实"的规则 (T-01 ~ T-03)

判定为"属实"的漏洞具有实际危害，满足TSRC漏洞奖励标准，应生成完整报告并提交。

### T-01 — 完整攻击链 / 高敏感数据未授权获取

**条件：** 可直接获取或证明可获取敏感数据，且为目标系统核心信息。

**TSRC 核心场景：**
- 远程任意命令执行（RCE/代码执行）
- SQL注入获取可执行权限
- 直接导致严重信息泄漏（影响微信/QQ/王者荣耀等平台用户身份信息）
- 任意QQ/微信帐号密码更改漏洞
- 直接影响现金的漏洞（提现无限制，金额超10万）
- 服务器级别关键凭证泄露（AK/SK/证书/密钥可登录CVM）
- 批量获取用户敏感数据（3+敏感字段，1万+条 → 高危；100万+条 → 严重）

### T-02 — 权限绕过 / 未授权访问

**条件：** 可绕过认证直接访问受限资源，或越权访问他人数据。

**TSRC 关键判定：**
- **200 + 敏感数据 → confirmed**（如直接返回用户个人信息、订单数据等）
- **200 + "Unauthorized"/"没有接口访问权限" → suspected**（可能只是端点暴露但认证正常）
- **401/403 → 非未授权漏洞**（除非证明可绕过）
- **已登录状态下测试的越权 → 可接受**
- 未授权访问管理平台并使用管理员功能 → 高危

### T-03 — SSRF 实际可访问内网且有回显

**条件：** 使用TSRC指定测试域名/IP验证，可获取回显内容。

**分级（TSRC SSRF评分）：**
| 类型 | 等级 | 积分 |
|------|------|------|
| 无回显SSRF | 中 | 3 |
| 仅图片回显SSRF | 中 | 4 |
| 部分回显SSRF（回显字数有限制） | 高 | 6 |
| 全回显SSRF | 高 | 7 |

## 四、TSRC 等级判定表

| 等级 | 典型类型 | 积分范围 |
|------|---------|---------|
| **严重** | RCE、代码执行、严重信息泄漏(>100w条3+敏感字段)、核心产品命令执行、任意账号密码更改、直接影响现金(>10万) | 9-10 |
| **高危** | 存储XSS（核心产品/低交互/易传播）、SQL注入(可读表字段)、未授权管理后台、高风险信息泄露(>1w条3+敏感字段)、客户端远程代码执行、全回显SSRF、任意文件读写、重要系统越权 | 6-8 |
| **中危** | 需交互XSS、CSRF、普通信息泄漏、qq.com/tencent.com子域名劫持、OAuth劫持、无回显SSRF、本地任意代码执行、非核心SQL注入、任意文件读取、JSONP劫持 | 3-5 |
| **低危** | 反射XSS(非流行浏览器)、GitHub泄露、URL跳转、短信轰炸、minor信息泄露、盲SSRF | 1-2 |
| **无** | Bug、Self-XSS、无意义CSRF、401认证钓鱼、用户遍历、SPF、无回显SSRF但无法请求内网、本地拒绝服务 | 0 |
