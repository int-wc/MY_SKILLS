# 深度挖掘方法论

本文档定义补天SRC漏洞挖掘的核心方法论和思维模式。

## 核心原则

### 思维层次

```
反思为主 → 迁跃为辅 → 分析为底 → 扩展为路
```

- **反思为主：** 先深入分析已有资产和已知信息，不急于扩展新目标。对每个资产反复思考：这个系统是做什么的？数据流是怎样的？鉴权是如何实现的？
- **迁跃为辅：** 在深入分析的基础上，从一个漏洞发现跳跃到相关系统/服务，寻找横向关联
- **分析为底：** 所有判断基于实际数据（HTTP响应、JS源码、组件版本），不做无根据的猜测
- **扩展为路：** 在已有发现基础上逐步扩展攻击面，而非盲目扫描

### 第一性原理

遇到问题时，回到最基本的事实：
- 这个HTTP请求到底发送了什么？响应里到底返回了什么？
- 这个端点是否真的需要认证？认证是怎么做的？
- 这个系统的数据是从哪里来的？流向哪里？

**禁止：** 基于假设而非证据的判断。每一个结论必须有HTTP请求/响应作为支撑。

### 扩散思维链

从一个发现出发，沿着以下方向扩散：

```
发现A → 同域名不同端口 → 同网段其他IP → 同备案其他域名
     → 同组件其他实例 → 同框架已知漏洞 → 同系统默认配置
     → JS中引用的内部API → API中引用的内部服务 → 服务中的配置信息
```

**关键：** 每步扩散都要有实际请求验证，不建立在未经证实的假设上。

## 漏洞挖掘策略

### 多链路API漏洞联动

最有价值的漏洞往往不是孤立存在的，而是多个弱点组合形成的完整攻击链：

```
[信息泄露] → [获得内部API路径] → [未授权访问内部API] → [获取用户数据] → [越权批量拉取]
```

**联动技巧：**
1. 从JS中提取的API路径 → 直接测试未授权访问
2. 从一个API返回的错误信息 → 找到其他端点
3. 从Swagger/Actuator暴露的端点 → 逐一测试鉴权
4. 从一个系统的弱口令 → 横向移动到同网段其他系统

### 隐藏API发现策略

不依赖固定的路径字典，通过以下途径发现隐藏API：

1. **JS逆向**（首选）：从JS源码中提取所有路径字符串和请求构造逻辑
2. **错误信息泄露**：404页面、调试信息、异常堆栈中可能暴露真实路径
3. **配置文件泄露**：`.env`, `.git/config`, `web.xml`, `application.yml` 等
4. **注释和文档**：HTML/JS注释中的TODO、FIXME、开发笔记
5. **Source Map**：`.js.map` 文件直接还原原始源码结构和路由
6. **Webpack chunk**：chunk命名直接暴露功能模块名

### 长利用链构建

从低危到严重，串联多个弱点：

```
初始入口（低危/中危）
    ↓
权限提升/横向移动
    ↓
敏感数据获取/系统控制（高危/严重）
```

**构建步骤：**
1. 识别初始入口（信息泄露、未授权端点、弱口令等）
2. 分析入口能获取什么信息/权限
3. 基于获取的信息，寻找下一步可访问的资源
4. 重复直到达到高危/严重影响
5. 在报告中清晰画出完整攻击链

## 漏洞优先级（红队视角，按赏金排序）

```
1. 真实获取系统/应用权限 (RCE/WebShell)
2. 真实公民三要素等敏感数据泄露 (身份证/银行卡/手机号)
3. 任意文件读取
4. 任意文件下载
5. 任意文件上传
6. RCE / SSRF到内网 / 认证绕过等红队相关高危
7. 批量越权获取用户数据
8. 核心业务逻辑漏洞（支付/订单/账户）
9. 大量一般信息泄露
10. 存储XSS / CSRF / 一般越权
```

## 漏洞挖掘心态

- **保底原则：** 每个目标至少要挖出一个中危或低危漏洞作为保底
- **以高危和严重为主要目标：** 优先寻找 RCE、大量数据泄露、认证绕过
- **重视JS逆向：** 现代Web应用的前端代码是最丰富的攻击面信息来源
- **不放过任何200 OK：** 每个返回200的端点都值得深入分析其响应内容
- **对401/403保持诚实：** 401/403不等于漏洞，除非证明可绕过或实际含敏感数据
